# 常见问题与排查

[文档目录](README.md) · [外部接管](external-takeover.md) · [安全报告](../SECURITY.md)

## 启动和安装

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 DLL、引擎、模型或原生规则程序 | 重新完整解压对应平台发布包，保留 `Engine`、`Native`、`Assets` 与运行时文件；不要仅复制启动程序 |
| 下载的是源码 ZIP，无法运行 | 下载 Release 中的平台应用附件，或按[开发指南](development.md)构建 |
| macOS 无法确认来源 | 核对仓库和 Release 签名说明，使用系统提供的打开确认；不要关闭全局系统保护 |
| 更新后权限失效 | 检查系统设置中的应用副本、路径与签名；按提示重新授权并重启 |
| Windows 能编译但规则组件缺失 | 托管构建不生成 Windows 宿主所需的一切原生文件，按[原生构建](development.md#原生规则构建)准备 `PaddiRules.exe` |

## 连接、识别与轮次

**找不到窗口或画面空白**：保持目标未最小化，核对录屏权限，刷新窗口列表。硬件加速、镜像客户端、跨桌面与目标停止渲染都会影响捕获。无法获得新帧时，程序应等待，不应继续使用旧画面落子。

**棋盘位置不对**：窗口缩放、尺寸或显示器变化后重新定位。检查 90 个交叉点是否对齐棋子中心，朝向是否正确。局面校对窗口可以刷新图像与重做定位。

**某个棋子被认错**：先停止输入，打开“接管记录”，对比程序局面、变化前与图像识别棋盘。必要时在编辑窗口修正，再重新同步。不要只描述“引擎走得差”，需区分当时采用的棋子、轮次和最终着法。

**轮到哪方一直待识别**：静态棋子分布不能证明轮次，特别是中途接入。等待下一手可确认的合法走子，或核对目标后手动指定。图像识别 FEN 中的轮次不是独立可靠证据。

**对方已经吃子，程序仍保留旧棋子**：保留对应事件和前后截图，检查是否处于移动动画、识别冲突或捕获停滞。新版发送前核验会拦截不一致局面；仍有复现时提交[缺陷报告](#有效的缺陷报告)，不要覆盖／删除出错会话后才取证。

**标准开局与截图不同**：“标准开局”生成可编辑的标准布局，不代表自动识别成功，也不改变外部游戏。按截图修正或取消，改用自动识别。

## 输入不生效或停止

**已连接但不走棋**：连接阶段只观察和预计算。先核对接管方、轮次、执棋设置，再点击开始。轮次未知、识别冲突、尚有未确认输入时也会暂停发送。

**后台窗口事件不被接受**：目标可能拒绝后台输入。停止并核对局面后，选择自动聚焦或系统鼠标模式。已经部分发送的输入需要先确认结果，不要盲目连点开始重发。

**系统鼠标落点不正确**：检查窗口尺寸、DPI、遮挡和定位，确保目标可命中。可交互浮层与透明的穿透浮层行为不同。

**Windows 移动鼠标就漏点**：请使用 v1.0.6 或更新版本。旧版悬停后发送的按钮事件使用当时的光标位置，物理鼠标移动会改变落点；新版按下、抬起各自绑定坐标。系统鼠标仍共享光标，切换焦点或主动点击其他程序不属于独立后台控制。

**路线已经显示却不落子**：路线可能来自搜索中的 `info`，不能单独证明已经收到 `bestmove`。先看状态是“计算”“核验”还是“等待输入确认”，并在“接管记录”对比决策、发送和确认时间。v1.0.5 已修复高亮脉冲导致逐像素核验反复等待的问题；其他识别冲突仍需查看实际记录。当前搜索使用 `go movetime`，没有启动 `go ponder`；`bestmove ... ponder ...` 中的预测应手不表示客户端正在后台 Ponder 搜索。

**Windows 引擎正常但模拟输入被拒绝**：如果 JJ 等目标以管理员身份运行，而客户端不是同等权限，Windows 可能拒绝输入。优先将目标退出管理员模式，再重新连接；更换引擎或延长思考时间不能解决输入权限问题。

**点击停止后目标仍完成了当前一步**：操作系统或目标已经接收的输入不能被撤回；取消会阻止后续输出并尝试释放输入状态。程序保留待确认着法，继续时先核验。

**出现“等待核验”**：这通常表示当前证据不足或存在冲突。先观察状态与历史事件；持续无法恢复时，停止、校对并重新同步。降低稳定性门槛不是可靠修复。

## 引擎、模型和性能

| 现象 | 检查与处理 |
| --- | --- |
| 插件检测失败 | 检查系统架构、执行权限、UCI 象棋支持和程序自身依赖；原默认引擎会保留 |
| NNUE 无法加载 | 使用该版本兼容权重；外部插件不会自动套用内置 NNUE |
| 模型无权限／拒绝访问 | 核对账户、Key 和模型授权；目录中存在 ID 不保证可调用 |
| 思考等级不支持 | 选择服务实际支持的等级；程序不自动偷偷降级 |
| 模型返回非法着法 | 响应必须属于经过校验的候选且仍对应当前棋局；无效回复不会直接发送 |
| 规则选项与目标游戏不同 | 外部游戏负责最终裁定；模型原生裁判固定为 0906，不跟随任意插件设置 |
| Hash 增大后卡顿 | 检查可用内存和其他进程，减少换页；更大 Hash 不一定更快 |
| 33 ms 设置仍然等很久 | 该数字只是目标观察间隔；分别检查动画、OCR、搜索／网络和输入耗时 |
| 显卡很强但 NPS 没增加 | 随包 Pikafish 使用 CPU；远程模型也不由本机显卡加速 |

详细参数见[性能说明](performance.md)，模型接口见[引擎与模型](engines-and-models.md)。

## 历史与复盘

**旧棋局没有识别事件**：旧 `Recovery` 文件只有棋谱。自动日志只能从支持该功能的版本建立会话之后开始记录，不能追溯补出过去没有保存的事实。

**“加载棋谱复盘”禁用**：实时连接或相关操作仍在进行时可以看事件，但不能把历史棋局替换成当前接管棋局。先断开，再加载。

**图像识别预览不显示**：事件可能没有完整识别 FEN，或结果无法解析。缺少字段时按钮禁用；非法结果显示原因，原始详情仍可查看。

**保存失败**：检查用户数据目录权限、磁盘空间和文件是否被其他程序占用。保留错误信息；不要把仅存在内存中的本局当作已持久保存。记录路径与内容见[数据与隐私](privacy-and-data.md)。

## 有效的缺陷报告

在 [Issues](https://github.com/PaddiSoft/PaddiChess/issues) 提供：

1. 发布版本／提交、操作系统、CPU 架构、目标应用和窗口缩放。
2. 使用本地对弈还是外部接管，接管方、朝向、轮次设置与输入模式。
3. 最短复现步骤、预期行为、实际行为和发生时间。
4. 相关 `.paddi.json` 与前后事件；识别问题附授权截图，尽量包含出错前／后局面及动画上下文。
5. 引擎版本、NNUE、线程／Hash／时间，或模型 ID 与思考等级；无需 Key 或私人服务地址。

截图请去除无关账户和窗口内容；日志请检查路径、个人注释、模型自由文本与凭据。涉及密钥泄露、任意执行或越权输入时，按 [SECURITY.md](../SECURITY.md) 使用私密报告流程。

## 棋子仍然识别不确定

v1.0.3 默认使用象棋专用模型。先确认网格交点和朝向，再使用“刷新截图并识别”；少量不确定格会自动文字补识。需要全盘中文 OCR 时，点击“文字补识”，这个操作较慢。不要用标准开局覆盖已经走过棋的局面。若每次连接都异常缓慢，请确认完整解压了发行包中的 `Assets/Recognition` 和 `Assets/Ocr`，模型损坏时会回退到完整 OCR。
