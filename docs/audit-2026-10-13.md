# 2026-10-13 工程检查

[文档目录](README.md) · [工程架构](architecture.md) · [开发与验证](development.md)

基线为 `24f3b7b`（v1.0.13）。本轮检查涵盖 Core、Engine、External、Sessions、Services、Avalonia 窗口／控件，以及原生桥接入口、依赖、测试与发布流程。采用源码检查、缺陷回归、完整构建测试和发布内容扫描；没有发起真实 JJ／天天象棋连续对局。

## 本轮修复

| 问题 | 影响 | 处理与验证 |
| --- | --- | --- |
| 后台核验缓存的相同画面分支只比较中心采样 | 曾用上浮采样确认的棋子，外围字形变化后仍可能复用旧结果 | 相同画面检查同时验证原观察实际使用的上浮样本及标定；回归构造中心完全相同、上浮区域变化的画面，要求重新识别 |
| 识别模型串行锁等待无法响应取消 | 其他推理较慢时，已经超时或被停止的请求仍占着等待任务 | 改为可取消的信号量等待；测试保持一个模拟原生推理未完成，要求排队请求先取消，随后模型仍正常可用 |
| 引擎输出队列和诊断累计无界 | 第三方插件大量输出时内存持续增长 | UCI 队列容量 1024，满时等待、不丢 `bestmove`；标准错误输出以固定缓冲排空；测试暂停消费者、输出 4097 条搜索信息和大量诊断后仍正确完成 |
| 历史读取只忽略旧结果，未取消旧任务 | 快速切换／关闭记录窗口仍进行无用 I/O；缓存命中时解析可能连续运行在 UI 线程 | 刷新、选择、复盘均绑定独立取消源；读取／解析移出 UI，保留版本检查和原子文件共享行为 |
| 平台测试和引擎文件缺失时直接返回 | 测试报告把未执行内容记为通过；带 RID 的输出层级可能找错源码根目录 | 平台不适用明确跳过；必需引擎缺失明确失败；从应用输出目录读取配套引擎及 NNUE |
| Windows CI 主要运行定向子集 | 存储、界面、引擎及其他模块的 Windows 回归覆盖不足 | 扩展为完整 CPU 测试项目，保留自动推理检查和自有 Win32 窗口输入测试 |
| Windows 完整回归发现历史快照替换失败 | 正在查看接管记录时，覆盖式移动被 Windows 拒绝，后续记录写入随之失败 | 已存在的快照使用 `File.Replace`，初次保存仍用移动；验证两个旧读取句柄保持打开时，第三个快照仍能发布、旧句柄内容不变 |
| macOS 自动加速回归暴露补识重启循环 | 某批 OCR 超过 800 ms 时，中途取消会丢弃结果，下次仍重跑同一批；已完成输入缓存不能解决一批也完不成的情况 | 将补识调度预算落实到完整批次之间，至少完成一批并缓存再让出；会话停止／上层核验取消仍生效。零软预算回归验证慢批次仍能逐次推进，最后准确识别原先误作车的卒 |

扩大 Windows 测试范围还发现定位测试的人工图片把内七路连续画过了河界。使用 Times New Roman／Courier New 在 macOS 也能复现同样的偏移，说明不是 Windows 截图后端问题。定位测试已补齐象棋河界，保留原有坐标精度断言；没有按平台／皮肤改定位器或放宽断言。

本轮没有为特定棋盘皮肤添加规则，也没有降低棋子身份核验阈值。缓存改动用于确保新证据确实对应当前画面；它不能单独证明所有真实游戏中的核验停滞都已消失。

## 后续项落实（同日第二轮）

此前表格中的工程改进已落地，完整说明见 [工程改进与性能验证](engineering-followup.md)。

| 范围 | 本次完成 | 验证入口 |
| --- | --- | --- |
| 接管时延 | 捕获、跟踪、完整识别、核验、搜索、结果到输入、原生输入的有界 P50／P95／P99；本地帧清单回放命令 | 接管记录中的性能统计、`--recognition-benchmark` |
| 推理隔离 | 常驻识别子进程、原始 BGRA 通信；取消／超时终止原生阻塞，下次 CPU 重启；CPU 就绪即接收请求，GPU 后台预热 | 真进程复用、挂起进程取消与 CPU 重启测试 |
| 规则能力 | `IRuleMoveProvider` 与 `RuleCapabilities` 明确区分 UCI 规则选项和合法候选查询；界面显示模型实际使用的规则组件 | UCI 能力边界与候选验证测试 |
| 会话工程 | `ExternalSessionCoordinator` 管理搜索生命周期、识别刷新、双帧核验、输入重试与捕获节奏 | 原有接管错序、暂停、取消、快速应手和新增协调器回归 |
| 模型网络 | HTTP 传输、协议解析和选招决策拆为三个职责清楚的类，保留现有公开调用方式 | JSON／SSE／工具调用／错误回显与重试回归 |
| 历史 | 会话分页、128 行事件索引、默认最新页、旧记录延迟建索引、摘要；用户检查占用后确认清理，活动记录持锁保护 | 不完整尾行、分页顺序、活动记录保护、Windows 快照共享、界面测试 |
| Linux | X11 Composite 独立窗口捕获、XTest 前台点击／拖动，独立进程保护 GUI；增加 Xvfb 实窗 CI | 遮挡后的捕获和两次点击坐标测试；Wayland 暂不支持 |
| 依赖与资源 | 四个发布 RID 的漏洞查询、许可清单覆盖、72 项资源／notice 哈希和公开内容扫描，纳入 CI 与打包入口 | `Dependency and asset audit` 工作流 |
| 测试可信度 | 修复无返回值异步 UI 测试没有被完整等待的问题；延迟抛错测试验证断言确实传播 | `AwaitedUiSession` 与完整回归 |
| 安装包版本 | macOS `Info.plist` 从 MSBuild 版本生成，避免应用信息滞后于程序版本 | 签名前生成，上传前与 Release 标签核对，下载实际安装包复核 |

这里的“完成”指上述工程实现与可执行验证。真实第三方游戏、全部显卡／NPU、任意皮肤的效果需要对应环境证据；不能由 CI 或单张截图证明。Linux 支持范围是 X11 前台输入，未宣称 Wayland 或任意程序后台输入可用。窗口保留界面编排职责，不把本次协调器提取称作所有页面完成 MVVM 重写。

## 验证方式

```bash
PADDI_RECOGNITION_DEVICE=cpu bash scripts/verify.sh
python3 scripts/audit-publication.py
dotnet list PaddiChess.slnx package --vulnerable --include-transitive --format json
git diff --check
```

完整回归覆盖局面规则、引擎、识别、接管状态机、输入取消、摆棋覆盖、数据恢复和多尺寸布局。Windows 与 macOS 的结果、平台跳过项分别保存在对应提交的 GitHub Actions `windows-recognition-evidence`／`macos-regression-evidence` 中；本机日志保留于 `artifacts/`，不作为源码提交。

性能判断应使用相同输入、同样的预热条件和相同硬件。模拟输入测试通过说明客户端调度能正确推进，不能直接转换成真实小程序的点击时延或全皮肤识别准确率。
