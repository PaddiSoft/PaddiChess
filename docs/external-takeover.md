# 外部棋盘连接、接管与历史

[文档目录](README.md) · [排查指南](troubleshooting.md)

## 连接和开始是两个动作

**① 连接并同步**读取目标窗口、定位棋盘、识别棋子并持续观察。已确认轮到接管方时可预计算，此阶段不发送点击。

**② 开始接管**才允许提交落子。已有结果也必须复核最新局面；改变棋局、轮次、模型或执棋配置后，旧结果不能直接继续使用。

| 状态 | 行为 | 操作 |
| --- | --- | --- |
| 未连接 | 无实时接管会话 | 选择窗口、检查权限、连接 |
| 已连接、尚未开始 | 观察和预计算，不发送落子 | 核对棋局、设置接管方、开始 |
| 接管中 | 确认轮次后计算并核验输入 | 停止、Esc、查看记录 |
| 等待核验／恢复 | 识别冲突、捕获中断或输入待确认时暂停发送 | 等待恢复，或停止后校对／重新同步 |
| 已暂停 | 保留棋谱、连接与未确认着法 | 继续、重新同步、断开 |
| 本局结束 | 保留终盘、结果和棋谱 | 复盘、接管下一局 |

## 首次连接

1. 打开目标棋盘，保证棋盘完整可见且窗口未最小化。
2. 进入“外部接管”，完成平台权限检查。
3. 选择目标窗口，点击“① 连接并同步”。
4. 对照原图核对棋子、朝向、当前轮次和接管方。默认接管棋盘下方，可改成固定红方或黑方。
5. 选择默认引擎或模型；模型同时选择服务、型号和思考等级。
6. 点击“② 开始接管”，观察首次落子与确认状态，确认目标接受所选输入方式。

对手在连接阶段走棋，观察循环会继续同步。中途接入无法可靠判断轮次时，保持待识别，等待下一手合法着法或明确的轮次证据；也可手动指定当前方。**图像识别 FEN 的轮次字段可能沿用请求参数，不能单独证明外部轮次。**

## 标准开局与图形校对

点击常驻的 **标准开局**，先停止自动输出并暂停观察，再按当前朝向生成标准 32 子、红方先行，打开图形局面窗口。对照截图放置、移动或擦除棋子，修正朝向和行棋方后采用局面。

- 不向目标游戏点击“新局”，不改变目标棋盘。
- 目标不是标准布局时，应手动修改或改用识别结果。
- 取消校对保留原棋局；此前观察可恢复，自动发送仍需明确开始。
- 采用不同局面前保存旧会话记录，避免重新同步覆盖出错证据。

一般的局面编辑窗口还支持刷新截图、重新定位棋盘、修正不确定位置。窗口尺寸或方向改变后，以新截图与几何信息核对。

## 识别、轮次与发送前核验

正常追踪综合棋盘观测、已确认棋子样本、完整棋子身份与合法续着；必要时由离线象棋专用模型恢复，中文 OCR 补查少数不确定位置。像素发生变化，不等于棋子已到最终落点。

一手着法从候选到可发送，需要满足以下条件：

1. 画面能与已确认棋局和合法变化对应。
2. 移动动画、途经交叉点得到稳定落点核验；漏采时可尝试恢复相邻两手。
3. 行棋方已确认，而且轮到接管方。
4. 决策仍对应当前 FEN、起始局面、完整已确认历史及执棋配置。
5. 输入前重拍目标，核对窗口身份和尺寸，并独立核验棋子。可信棋子识别与快速匹配冲突时，拦截本次落子。

不满足条件时保留会话并继续观察，不把未确认的新 FEN 直接变成可以行动的棋局。标准开局的用户确认同样不绕过后续核验。

这些步骤不能补出接入前的历史。长将、长捉和循环判断只能基于程序已知的起始 FEN 与后续着法；外部游戏的最终裁定仍以该游戏为准。

## 更换棋盘外观与显示器

自动定位比较明线、暗线候选，通过九列十行、河界和边界的几何结构选择网格。离线识字读取交叉点附近的字符，归一化棋面、字形与对比度，再用具有阵营含义的字和图中实际颜色确认红黑；新增截图只进入回归测试，不为每套皮肤添加识别分支。

手动对齐网格能排除定位误差，但无法补回小字、模糊、动画遮挡造成的字形信息。不可靠位置保留为“待核对”，不能以“数量合法”替代棋子识别，也不能凭空补齐标准开局。主动选择“标准开局”是单独的用户编辑操作。

macOS 14 及以上的持续捕获使用窗口实际像素分辨率，保留 Retina 字形细节。在窗口逻辑尺寸不变时，截图像素倍率变化会同步重算网格，清除旧采样缓存，并在发送前重新核验。真正改变窗口大小仍可能引起布局重排，需要重新定位。捕获尺寸超出资源上限时明确报错，不静默压低分辨率。

## 暂停、重新同步与断开

**停止 / Esc**取消继续发送，保留棋谱和已提交但尚未确认的着法。取消在两次点击之间发生时，不能假定目标完全没有收到输入；恢复时先核验，避免重复提交。

**重新同步**优先用历史解释最新画面，补回遗漏着法或修正近期错误匹配。只是几何／外观刷新且棋局相同，保留同一棋谱；采用无法对应原历史的新局面前，结束旧记录并保存恢复棋谱。

**断开**结束当前会话，返回本地查看棋局，自动历史保留。重新连接建立新会话。**接管下一局**重新读取目标，不沿用上一局的轮次、终局截图或手动轮次修正。

稳定画面中已确认的绝杀可结束会话。引擎预测“杀 N”、暂时无候选、普通重复和未确认画面都不等于已确认的外部终局。

## 查看当时认成了什么

点击控制区标题旁的 **接管记录**。会话、事件、原始详情与事件棋盘并排显示；连接中可查看，断开后可加载整份棋谱复盘。

| 预览 | 内容 |
| --- | --- |
| 程序局面 | 事件发生时程序采用的棋局 |
| 变化前 | 保存的更改前局面，无字段时禁用 |
| 图像识别 | 识别出的棋子分布，可能尚未采用；行棋方以确认记录为准 |

预览只读，可翻转，不会发送输入或改变当前棋局。无法解析的记录显示原因，原始文本仍保留在详情中。

事件包括开始、识别候选、确认落子、选择着法、发送、等待核验、自动校正、暂停、异常与结束。**发送表示提交输入操作，确认落子才表示画面支持该着法。** 校正前后的 FEN 便于追查错误分支。

每会话在本机独立保存：`game.paddi.json` 可复盘，`history.jsonl` 按序记录事件。状态与候选只追加小日志，不反复写整盘；开始、确认、校正、暂停等节点保存快照。历史不保存 API Key，也不持久保存完整屏幕截图。旧 `Recovery` 棋谱可并列查看，但不能补回过去从未记录的识别事件。

## 输入方式与平台边界

| 平台／方式 | 行为 | 边界 |
| --- | --- | --- |
| macOS 系统鼠标 | 系统指针点击／拖动 | 目标落点必须可命中，交互遮挡可能阻止输入 |
| macOS 窗口事件·后台 | 定向发送，不主动切前台或移动指针 | 目标须接受后台事件，跨桌面与镜像客户端需实测 |
| macOS 窗口事件·自动聚焦 | 输入时激活目标 | 可能切换前台窗口或桌面 |
| Windows | 窗口捕获与平台输入 | 权限、DPI、硬件加速绘制和桌面状态影响兼容性 |
| Linux | 暂无外部接管实现 | 可构建本地客户端 |

最小化或停止渲染的窗口不一定提供新画面。捕获失败时等待有效帧，不将旧缓存图假装实时。实时／均衡／省电是观察目标间隔，不保证在该时间内完成识别、搜索、输入和游戏响应。

反馈识别问题时，提供相关事件、前后两三张经授权并适当脱敏的棋盘截图、缩放、主题和输入方式，见[排查指南](troubleshooting.md)。


### 计算完成后迟迟不落子

搜索预算只限定引擎计算。状态会分别显示计算、落子前棋盘核验、输入发送和截图确认；识别尚有疑点时会显示不确定位置数量。接管记录中保留核验、补发终点及实际确认的时间，可以定位延迟发生在哪一段。

- 核验在后台执行，截图同步继续运行。计算好的着法按局面和完整棋谱绑定，核验重试不会重新请求模型或重复计算。
- 持续高亮、颜色脉冲不再要求整盘像素完全相同：用独立完整识别建立临时字形样本，重新辨认发生变化的格点；棋子身份冲突、位置变化或新局面仍会阻止旧着法。
- 若原输入只选中了起点，必须同时看到起点的选中反馈，并连续确认整盘棋子尚未走动，才允许补发终点；最多两次。静止的旧截图、未确认的输入、停止后恢复均不能授权盲目重放起点。
- Windows 点击保留悬停和按下间隔，并检查系统是否接受输入；最终是否走子仍由截图确认。目标以管理员身份运行时，建议先退出其管理员模式，与客户端使用相同权限。
- macOS 后台模式延长按下时长，并在终点释放后短暂保留窗口事件上下文。第三方程序仍可能拒绝非焦点事件；遇到持续拒绝可选择“窗口事件 · 自动聚焦”。

这些机制不保证任意第三方程序支持跨桌面后台控制。引擎完成不等于棋盘已核验，也不等于目标已接受点击。

### Windows 落子时移动鼠标

Windows 的系统鼠标模式共享桌面指针。每次按下和抬起都在同一个原生输入事件内带上落点坐标；两次点击、补发终点和拖动释放都使用这一方式，避免悬停／按住期间的鼠标移动把按钮事件送到别处。多显示器按整个虚拟桌面的物理像素定位，包括主屏左侧或上方的屏幕。

这不是独立的后台鼠标：落子仍会移动系统光标，第三方游戏也可能处理按住期间的物理鼠标移动。主动点击其他窗口、拖动棋盘窗口或遮挡落点会中断发送；此时释放按键并核验结果，不盲目重发整步。纯鼠标移动不再要求整段点击期间保持光标不动。

原生回归测试在自建 Win32 窗口中于悬停和按下之后实际移动系统光标，检查起点、终点、补发和拖动的按钮坐标；此测试不代替 JJ 等第三方游戏的实战验证。
