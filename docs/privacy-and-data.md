# 数据与隐私

[文档目录](README.md) · [安全报告](../SECURITY.md)

## 哪些计算在本机进行

本地棋盘、UCI 引擎搜索、原生规则校验、棋盘定位、样式匹配、象棋专用模型与 OCR 均在本机进行。识别模型均随包提供，运行时不需要把截图上传到识别服务，也不需要临时下载识别模型。

外部接管会读取所选目标窗口的画面，并按用户选择的模式提交鼠标／窗口事件。操作系统授予的录屏和辅助功能权限范围可能大于一次接管操作；可在系统设置中撤销权限。

## 使用模型 API 时发送什么

主动配置模型服务后，获取模型目录、连接测试和对弈请求会联系该服务。选招请求包含当前 FEN、允许的 UCI 候选、对局指令，以及需要时的提和上下文。截图本身不是选招请求的组成部分。

API Key 作为鉴权信息发送至配置地址。远程地址要求 HTTPS，本机地址可使用 HTTP。服务端如何保留请求、是否用于训练、费用和访问控制，由对应服务的政策决定；客户端不能替代服务方作保证。

Key 只放在本次进程内存中，不写入 `settings.json`、棋谱或接管历史，退出后重新输入。应用会遮蔽已知当前 Key 在模型可见说明中的直接回显；这不等于对任意自由文本中的所有隐私信息自动脱敏。

## 本机保存内容

| 内容 | 位置／形式 | 说明 |
| --- | --- | --- |
| 偏好 | 数据目录的 `settings.json` | 显示、引擎路径与选项、服务名称／地址、模型目录、启用状态、选手偏好；不含 Key |
| 识别样式 | `BoardSkins/` | 本机学习／保存的棋子特征、样式等 |
| 自动接管棋谱 | `ExternalHistory/<会话>/game.paddi.json` | 初始局面、已确认着法、注释、评分和模型可见说明 |
| 接管事件 | `ExternalHistory/<会话>/history.jsonl` | 时间、类型、FEN、候选、发送／确认／校正等；可能含窗口标题、模型名称和错误说明 |
| 恢复棋谱 | `Recovery/*.paddi.json` | 替换不能续接的新局面前保存的旧棋谱 |
| 手动棋谱 | 用户选择的文件位置 | `.paddi.json`，分享前检查注释与模型说明 |
| 引擎插件配置 | 用户导出的 `.paddi-engine.json` | 可能包含本机程序和 NNUE 路径，分享前检查路径 |

自动记录不持久保存完整屏幕截图。部分平台兼容捕获路径可能创建本机临时图片，并在操作结束时清理；不要将“历史没有截图”理解为任何平台路径都永不接触临时文件。用户主动保存或提交的截图另行保留。

## 数据目录

应用通过 .NET `Environment.SpecialFolder.LocalApplicationData` 取得系统本地应用数据位置，再使用 `Paddi象棋` 子目录。

- Windows 的常见位置为 `%LOCALAPPDATA%\Paddi象棋\`。
- macOS／Linux 使用该运行环境返回的本地应用数据目录；不要假定源码目录或 `.app` 内部就是数据目录。
- 开发测试可设 `PADDI_SETTINGS_PATH` 指定独立的设置文件，其所在目录同时作为该次运行的数据根目录。

例如，运行隔离的开发实例：

```bash
PADDI_SETTINGS_PATH="$PWD/.local-test-data/settings.json" \
  dotnet run --project PaddiChess/PaddiChess.csproj --configuration Release
```

请将这种临时数据目录加入本地忽略，不提交其中设置或棋谱。指定自定义路径时，不迁移旧用户数据目录。

旧 `PikaDesk` 目录仅作为兼容迁移来源：复制新目录中缺失的文件，不覆盖现有文件、不删除旧目录，失败可在后续重试。

## 保留与删除

会话记录用于复盘和追查，当前没有按天自动清理的策略。重连或重新同步不会覆盖旧会话。需要清理磁盘时，先关闭应用，备份需要保留的棋谱，再删除不需要的会话目录。

卸载／删除发布包不会自动清理数据目录。删除某个服务配置不撤销服务端的 Key；如凭据意外泄露，应在服务方撤销或轮换。

## 分享缺陷资料

优先分享问题前后几步的棋谱和相关事件，不必上传整个数据目录。检查并去除无关窗口、账户标识、聊天内容、个人路径、服务地址与自由文本中的敏感内容。不要分享 Key、鉴权头、签名证书或私钥。

真实棋盘截图、字体和主题资源需有提交／公开的权限。README 中的 JJ 象棋截图展示作者的测试记录；其他用户的截图仍需取得相应授权后才能公开。
