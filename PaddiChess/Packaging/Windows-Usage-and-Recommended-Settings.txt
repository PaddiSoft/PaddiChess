Paddi象棋 · Windows x64
版本：以下载的 Release 标签和程序版本为准。

一、启动

完整解压 ZIP，再双击 Paddi象棋.exe。保留 Engine、Native、Assets 及同目录的 DLL；请勿只复制启动程序。
发布包自带 .NET 10 运行时、Windows x64 Pikafish 2026-09-25 与 pikafish.nnue，无需另行安装 .NET。
这是便携版，在 Windows 上独立保存设置。包内没有 macOS 设置、模型 API Key 或用户棋谱。
设置目录：%LOCALAPPDATA%\Paddi象棋\settings.json。
当前包在 macOS 上交叉编译、检查，Windows 界面、音效与外部窗口输入仍需目标机器实测。
Windows 系统鼠标模式共享桌面光标。按下、抬起均绑定棋子落点，避免移动鼠标后按钮事件偏离；落子时仍会移动光标。主动点击其他窗口、遮挡或移动棋盘会中断发送并重新核验。
JJ 等目标请与客户端使用相同权限，优先退出目标的管理员模式；Windows 可能拒绝普通权限程序向管理员程序发送输入。引擎计算完成不代表目标已接受点击，可在“接管记录”检查决策、发送与确认时间。
顶部“引擎插件”可添加多个 UCI 象棋引擎与版本，独立绑定对应 NNUE 权重，然后检测并设为默认。
默认引擎统一用于执棋、分析与接管。外部版本不会自动使用内置 NNUE；留空权重时保留该引擎自身默认设置。
支持导入/导出 .paddi-engine.json 插件配置；移除列表项不会删除引擎程序。主界面分栏可拖动调整。
顶部按“对弈 / 外部接管 / 棋盘与搜索 / 引擎插件 / API 服务”切换工作区，切换保留棋局、棋谱、模型选择和调整过的分栏宽度。
引擎与模型使用完整配置区：左侧版本列表、右侧程序和权重；API 页左侧服务连接、右侧可用模型。
接管页同时显示棋盘、棋谱与分析、接管状态。窗口、轮次、接管方、执棋方式、模型等级、输入方式、开始/停止/重新同步直接显示。
自动连接成功后会持续同步棋盘并提前计算我方着法；对手在点击开始之前走棋无需手动重新同步。
“接管下一局”重新判断朝向与行棋方；无法确定时显示“待识别”，不会沿用上一局的修正。
确认绝杀后显示胜负与最后一手之前的搜索记录，点击棋谱可复盘；实时接管期间收起不可用的复盘按钮。
点击开始只允许提交当前仍有效的结果，每次落子前仍核验最新画面；未开始时不发任何点击。
更改模型、思考等级或搜索设置会取消旧计算。切换引擎插件前须停止实时同步，原棋盘与棋谱保留。

二、Ryzen 7 9800X3D / 48 GB RAM / RTX 5080 的建议起点

9800X3D 是 8 核 16 线程。以下为基于硬件与引擎工作方式的建议，不是该机器实测的最优值。

参数                     流畅外部接管              长时间分析 / 复盘
棋力等级                 20                        20
CPU 线程                 12                        16
置换表 MB                4096（4 GiB）             8192（8 GiB）
候选变化数 MultiPV       1                         1；对比多方案时改 2–3
额外深度限制             关闭（默认）              关闭；需要时明确开启
分阶段时间               默认关闭，可选开启        按需；手动分析使用统一时间
可选开局 / 中局 / 残局   0.8 / 5 / 5 秒            各阶段按对局时间自行设置
统一思考时间             5 秒，按剩余时钟调整       手动分析 30 秒，可增至 60–120 秒
开局截止回合             10                        10
残局子力阈值             6（车2，马/炮1）           6；预算分组，不代表复杂度
外部同步速度             实时优先（33 ms）         不适用
外部局面评分             自动：复用执棋评分        不适用

同时录屏或运行重负载程序时，可先把接管线程改为 8，再试 12。
希望接管棋力更高且对局时间允许，可把统一时间增至 8–12 秒。少子残局不必固定比中局更长。
20 级默认只按思考时间搜索，不附加深度上限。
如果明确开启深度限制（1–255），思考时间与深度任一达到就停止；不保证算到指定深度。
当前官方皮卡鱼主搜索内部最多报告 245 层。杀棋剪枝可很快达到高名义深度，不代表穷举所有分支；通常按时间搜索即可。
旧版保存的深度数值会保留，但不会在未明确开启开关时限制搜索。
分阶段时间只作用于 20 级执棋，包括外部接管；手动分析仍使用统一思考秒数。
支持标准开局及首回合的合法局面中途接入；红方已走一手时仍判为开局，按真实起点偏移计回合。
其他中途局面不会仅因本地第一手就判为开局，会结合当前子力判断阶段。

建议使用“按当前线程 / 置换表测速”在相同 Hash 下比较 8、12、16 线程，兼顾实际 GUI 流畅度。
超线程并非必然更快，NPS 也不能直接等同于棋力。以上是起点，不会自动覆盖你的偏好。
短时对局先用 4 GiB 缓存即可；长分析可比较 8–16 GiB。更大的 Hash 不保证更强，保留足够内存给系统与其他应用。
置换表上限已扩到 16384 MB；修改容量会重新分配缓存，适合在开始搜索前设置。

三、识别加速与 RTX 5080

棋盘识别和中文 OCR 默认优先使用 DirectML（NVIDIA / AMD / Intel），失败自动回退 CPU。
Windows 10 1903 或更新系统可用；无需 CUDA。Windows 11 24H2+ 另检测已安装、认证、架构匹配的 NPU 提供程序，模型不兼容则跳过。
界面显示实际后端；首次编译在后台完成，期间仍由 CPU 识别。不要替换或遗漏包内的三个识别运行库 DLL。
这项加速用于棋盘识别。以下是 Pikafish 执棋引擎的情况：

当前官方 Pikafish 搜索与 NNUE 局面评估只使用 CPU，没有 CUDA / GPU 执棋加速开关。
NNUE 是为 CPU 上的小规模快速增量评估设计的；GPU 用于训练网络，不用于这个发行版的执棋搜索。
RTX 5080 可供界面绘制、录屏或单独部署的本地大模型使用；通过远程 API 调用模型时，模型运算在服务端。
GPU 象棋引擎（例如 Px0）采用不同架构，不能通过开启 Pikafish 的某个配置项获得。

五、长将、长捉与模型候选

皮卡鱼依据完整已记录棋谱，使用自己的长将、长捉和重复规则搜索。客户端已移除固定将军次数和重复次数的简化禁手。
在“引擎插件”选择版本，点击“检测引擎”，可直接看到该引擎声明的规则选项。内置 0925 版支持 Repetition Rule（默认亚洲规则，另有简易中规、天规等）、Draw Rule、自然限着等，选择后保存。每个插件独立保存规则，插件数量不设上限。
大模型先从 Native/PaddiRules.exe 获取通过原生规则校验的候选，再通过工具调用或结构化回复选择；越过候选的回复会被拒绝。
校验组件直接使用皮卡鱼 0906 的规则源码，不做棋力搜索、不加载 NNUE。普通和棋循环和评价差的走法不会被当成禁手。
组件常驻并缓存完整棋谱的校验结果；校验失败会暂停，不会跳过规则校验继续落子。
内置引擎低等级随机选招时也使用这份校验；外部插件使用自己的 bestmove，有 Skill Level 时传入所选等级。
模型候选裁判固定为 0906 规则，不会随内置 0925 或其他引擎插件的 Repetition Rule 改变；界面会提示。外部对局仍以目标游戏裁定为准。

六、界面与实时同步

接管工作台顶部显示连接状态、开始/停止，窗口选择框单独一行；轮次、自动判断、执棋模型与思考等级、输入、同步、定位和重新同步直接可见。棋谱和分析并排，模型记录保留在下方。小窗口自动压缩间距，重要控件无需展开二级菜单。
棋子移动有轻微抬起、落下和吃子淡出；界面切换使用 150 ms 淡入。接管每手动画最多 65 ms，快速应手积压最多约 100 ms。棋盘动画时长设为 0 可关闭界面和走棋动效。
截图采样改为直接读取像素并复用完全相同的棋子特征，减少分配；性能数字最多每秒刷新约 5 次，落子确认仍按所选同步频率运行。识别阈值与落点稳定核验保留，不能将“33 ms 同步间隔”理解为 33 ms 内必定完成识别落子。
中途截图不能恢复接入前的走棋历史，因此不能判断此前已经重复的次数。
Native/PikafishRules-source.zip 包含组件完整源码、构建脚本及 GPL 许可证。
